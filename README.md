# 노동시장 지표 포털

고용노동부 「**통계로 보는 우리나라 노동시장의 모습**」(연간, 202쪽)을 인쇄 대신
**공개 웹 지표 포털**로 옮기는 작업입니다. 매월 원자료를 다시 받아 수치를 갱신하고,
필요할 때 특정 기준연도로 조회·인쇄합니다.

담긴 수치는 모두 **이미 공표된 통계**입니다(국가데이터처·고용노동부·OECD 등).

---

## 무엇이 어려운 문제인가

책자는 엑셀로 만듭니다. API 로 받은 원자료가 시트에 쌓이고, **SUMIFS 계열 수식 37,467개**가
그것을 202개 지면의 표로 집계합니다. 웹으로 옮기려면 그 수식을 SQL 질의로 **번역**해야
하는데, 번역이 맞았는지를 사람이 눈으로 확인할 수는 없습니다.

그래서 이 저장소의 중심은 화면이 아니라 **대조 관문**입니다.

> 발간 확정본(`data/oracle/`)에는 **실제로 인쇄된 수치**가 들어 있습니다.
> 번역한 셀을 그 인쇄값과 **전건 대조**합니다. 하나라도 어긋나면 관문이 막습니다.

```
npm run verify
```

## 1단계 결과 — 관문 통과

| | |
|---|---|
| 대조 가능 | **29,561**칸 |
| 일치 | **29,558** |
| 불일치 | **0** |
| 실행 오류 | **0** |
| 파싱 못함 | **0** |
| 면제 (원자료 개정) | **3** |
| 부록·서식 (대조 제외) | 3,364 |
| **인쇄값 재현율** | **99.990%** |

시험 260개 · 시작 시점 70.493%(불일치 6,664)에서 올라온 수치입니다.

**면제 3칸**은 세종특별자치시 순이동(`p18` 2칸 · `p140` 1칸)입니다. 인쇄본이 현재
원자료의 **정확히 2배**입니다 — 세종은 시군구가 없는 유일한 시도라, 이 표가 과거 세종을
시도 행과 시군구 행으로 두 번 담았던 것으로 보입니다. 사용자가 「인쇄본이 틀렸다」고
판정했고, **확정본은 고치지 않았습니다**(확정본은 계속 「인쇄된 것」을 뜻해야 합니다).
면제는 좌표가 아니라 **차이 자체를 고정**하므로, 값이 또 바뀌면 다시 불일치로 돌아옵니다.

## 이 관문이 증명하지 **않는** 것

전체 브랜치 리뷰가 확인한 경계입니다. 적어두지 않으면 과장으로 읽힙니다.

- **일치 셀의 26.4%(7,804칸)는 데이터베이스를 타지 않습니다.** 평가 중에 발간본 통합문서에
  적혀 있던 값을 읽습니다. 즉 관문은 **셀별 번역**을 증명하고 **원자료부터 이어지는 전체
  경로**를 증명하지 않습니다. `data/oracle` 은 2025년 기준에 얼어붙은 값이므로, 2단계에서
  그 리터럴을 물화하지 않으면 그 칸들은 2025 에 정적으로 남습니다.
- **일치 중 586칸(2.0%)** 은 인쇄값이 `0` 또는 `-` 여서, 조건을 아무것도 맞지 않는 값으로
  바꿔도 여전히 일치합니다. 구조적 한계입니다. 반대 방향(오류를 `-` 로 덮어 통과)은
  없음을 확인했습니다.
- **부록·서식 3,364칸**은 외부 통합문서를 참조하지 않는 표시 로직이라 대조 대상이 아닙니다.

## 엑셀이 없어도 돌아갑니다

사용자 요구였습니다 — *「수식 한번 따가고 나면 로컬에 참고파일 없이도 수치 관리가 되도록」*.
원본 엑셀 폴더(845MB)는 사람이 **원데이터 → 수식엑셀 → 확정판** 한 사이클을 돌려야 나오는
결과물이고, git 으로 관리되지 않습니다.

그래서 되돌릴 수 없는 것만 저장소에 넣었습니다.

| 경로 | 무엇 | 왜 |
|---|---|---|
| `data/oracle/` | 인쇄된 값 | **정답표**. 확정본 엑셀만이 원천 |
| `data/cellmap/` | 셀별 질의 명세 | 열 이름이 해석 완료. **수식 문자열도 열 문자도 없음** |
| `data/layout.json` | 지면 구조 | 제목 195 · 출처기관 177 · 출처통계 144 |
| `data/gate-snapshot.json` | 관문 통과 시점 계산값 | 「번역 회귀」와 「자료 개정」을 가르는 기준선 |
| `data/formulas/` | 작업본 수식 | cellmap 의 원천 |
| `data/known-divergences.json` | 면제 | 사람의 결정 |

`data/raw/*.jsonl`(226MB)과 `data/obs.sqlite`(205MB)는 API 에서 재생성되므로 제외합니다.

**관문의 기본 경로는 물화된 cellmap 입니다** — 수식 파일도 헤더 매핑도 읽지 않습니다.
시험이 파일 열기를 감시해 그것을 확인합니다. 수식 경로는 `--from-formulas` 로 남아 있어
두 경로를 계속 대조합니다.

## 구성

```
tools/extract/     확정본·작업본 엑셀 → JSON  (read_only=True, save() 금지)
src/cellmap/       엑셀 수식 토크나이즈·파싱 → 질의 명세
src/query/         질의 실행, 기준연도 앵커 사슬 평가
src/verify/        확정본 대조
scripts/           관문(verify-all) · 물화물 생성기
docs/superpowers/  설계 스펙과 구현 계획
```

Node 24 내장 기능만 씁니다(`node:sqlite` · `node:test` · TypeScript 타입 스트리핑).
런타임 의존성 **0개**, 개발 의존성은 `typescript` 와 `@types/node` 뿐입니다.

```
npm test          시험 260개
npm run typecheck
npm run verify    대조 관문
```

## 기준연도

연도는 얼어붙어 있지 않고 **앵커에서 계산**됩니다.

```
앵커(기준연도) → _시계열 사슬 → 지면 연도 헤더 → SUMIFS 조건
```

13개 part 전부에서 앵커 2025 가 확정본의 연도를 재현합니다. 앵커를 2026 으로 옮기면
2,301칸이 따라 움직입니다. 원자료를 다시 받으면 수치가 함께 갱신된다는 뜻입니다.

다만 **통계마다 최신 공표 시점이 다릅니다** — 107개 표 중 26개가 2025 가 아닙니다.
그래서 2단계는 지표별 최신 연도를 기본값으로 쓰고, 기준연도를 입력하면 지표별로 범위를
깎습니다(2025 를 넣었는데 그 지표 최신이 2024 면 2024 까지).

## 진행

- **1단계 — 데이터 계층 · 전건 대조**: 완료 (관문 통과)
- **2단계 — 지표 포털 화면**: 설계 완료([스펙](docs/superpowers/specs/2026-09-11-2단계-지표포털-화면-design.md)), 착수 전
- **별도데이터 자동 수집**: 설계 완료([스펙](docs/superpowers/specs/2026-09-11-별도데이터-자동수집-design.md)), 착수 전

책자가 스스로 적어둔 것을 읽습니다 — 지면 셀 규약이 `A1` 제목 · `A2` 출처기관 ·
`C2` 출처통계표명이고, `C2` 가 `수기갱신` 인 지면이 **정확히 16개**로 그것이 자동 수집
대상 전체입니다. 그중 8개는 URL 까지 적어두고 있습니다. 패널 4지면은 마이크로데이터
분석 결과라 **자동화 불가로 명시**하고 수기 입력 경로를 유지합니다.

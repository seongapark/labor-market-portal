# 별도데이터 자동 수집 설계

**상위 스펙:** `docs/superpowers/specs/2026-09-10-노동시장-지표포털-design.md`
**결정일:** 2026-09-11
**범위 결정:** 사용자가 **층 0~1** 선택. 층 2~4 는 다음 회차로 미룬다.

## 1. 문제

별도데이터(`별도데이터.xlsx`)는 사람이 웹에서 받아 손으로 붙여 넣은 수치다. 매월 자동
갱신을 하려면 이 부분이 끊긴다. 사용자 요구: **웹에서 수집 가능한 별도데이터 원본
(hwpx, pdf, 스캔 pdf)을 자동 수집한다.**

## 2. 측정이 요청의 모양을 바꿨다

요청은 문서 파싱(hwpx/pdf)을 전제했지만, 실측 결과 **가장 큰 덩어리는 문서가 아니다.**

### 2.1 책자는 스스로 출처를 적어둔다

지면의 셀 규약: **`A1` = 지면 제목 · `A2` = 출처 기관 · `C2` = 출처 통계표명(또는 `수기갱신`)**.
195개 지면 중 `A2` 가 있는 지면 **177개**, `C2` 가 있는 지면 **144개**.

별도데이터 시트 자체도 1행에 출처를 적어둔다. **URL 을 담은 칸이 17개** 있다.

**규약을 읽되 믿지는 않는다.** 18개 지면은 `A2` 가 없고, 3개는 `A2` 가 `기준년도 -1`(출처가
아니다), 일부는 `A2` 에 기관 대신 표명이 들어 있다. 읽은 값은 확정본 대조로 검증한다.

### 2.2 수기갱신 지면은 정확히 16개 — 책자가 직접 선언한다

| 지면 | `A2` 출처 | 선언된 URL | 수집 방식 | 층 |
|---|---|---|---|---|
| `p116_117` `p118_119` `p120_121` | 중앙노동위원회 | `nlrc.go.kr/nlrc/policy/statistics/index.do` | **웹페이지 → 자료실 파일 다운로드** | **1** |
| `p239` `p240` | 한국생산성본부 | `stat.kpc.or.kr/integration/index` | **DB 조회 서비스** | **1** |
| `p122_123` | 고용노동부 | `moel.go.kr/info/publict/publictDataList.do?searchSeq=383…` | 첨부파일 | 3 |
| `p124` | 고용노동부 | `moel.go.kr/…searchSeq=384…` | 첨부파일 | 3 |
| `p125` | 고용노동부 | `data.go.kr/data/15068749/fileData.do` | 파일 API | 2 |
| `p64` `p65` `p66` `p67` | 고용노동부 **EIS** (사용자 확인) | `eis.work24.go.kr` Open API | API (§2.6 참조) | **0-b** |
| `p161` `p188` `p189` `p190` | 한국고용정보원 패널 | 없음 | — | **5 (불가)** |

**층 1 은 「간단한 HTML 긁기」가 아니다 (2026-09-11 사용자 정정).** 중노위는 웹페이지로
들어가 **자료실에서 파일을 내려받아야** 하고, 생산성본부는 **DB 조회 서비스를 이용해야**
한다. 즉 **문서 파싱이 층 1 에 바로 들어온다** — 다음 회차로 미룰 수 있는 것이 아니다.
내가 앞서 「문서 파싱 없이 층 1 만으로 막힌 셀이 0 이 된다」고 정리한 것은 틀렸다.

### 2.3 층 0 — 문서가 아니라 수집 목록 누락이다

`p49`(2,730칸)는 시트에 KOSIS URL 을 적어놨다:
`kosis.kr/statHtml/statHtml.do?orgId=101&tblId=DT_1DA7007` 등.

그 표들이 **`obs` 에 한 행도 없다**: `DT_1DA7007` `DT_1DA7006` `DT_1DA7A06` `DT_1DA7C06`
`DT_1DA7E06` (그리고 `nsist` 쪽 `…S` 변종). 누가 손으로 내려받아 별도데이터에 붙였을 뿐,
원래 API 로 받을 수 있는 표다. **파싱 문제가 아니라 수집 목록 누락이다.**

`p35`(지역내총생산, `A2` = 국가데이터처)도 같은 성격이라 층 0 에 함께 넣는다.

### 2.4 층 1 이 막힌 셀을 전부 설명한다

현재 관문에서 `etc` 때문에 막힌 셀은 **1,172개**이고, 전부 이 네 시트다:

```
p239_240   468      한국생산성본부
p116_117   286      중앙노동위원회
p120_121   220      중앙노동위원회
p118_119   198      중앙노동위원회
```

네 시트 모두 URL 이 선언돼 있다. 즉 **층 1 을 끝내면 막힌 셀이 0 이 된다.**
다만 §2.2 의 정정대로 층 1 의 수집 방식은 단순 HTML 이 아니다 — 중노위는 자료실 파일
다운로드(문서 파싱), 생산성본부는 DB 조회 서비스다. **문서 파서가 이 회차에 필요하다.**

### 2.6 층 0-b — EIS Open API (`p64~p67`)

사용자 확인: `p64~p67` 의 원천은 **EIS(고용행정통계)** 다.
안내 페이지 `https://eis.work24.go.kr/eisps/opiv/selectOpivList.do` 를 읽은 결과:

**서비스 3종뿐이다** — `OPIA`(구인·구직 현황) · `OPIB`(피보험자) · `OPIC`(실업급여).
`OPIA` 의 산출 필드가 `newJoNmpr`(신규구인인원) · `newJhntNmpr`(신규구직건수) ·
`empmCt`(취업건수) 로, **`p64~p67` 이 쓰는 수치와 일치한다.**

요청 규격:
```
https://eis.work24.go.kr/opi/joApi.do
  ?apiSecd=OPIA&rsdAreaCd=11110&sxdsCd=M&ageCd=01
  &rernSecd=XML&closStdrYm=202101&bgnPage=1&display=10
```
응답은 **XML 전용**(`rernSecd=XML` 필수). `display` 최대 10000.

**타당성에 걸리는 것 셋 — 실제 호출로 확인해야 한다:**

1. **`rsdAreaCd`(시군구 코드)가 필수다.** 안내 페이지에 **전국/전체/합계 코드가 없다.**
   `sxdsCd` 에는 `무관`(성별 무관)이 있으므로 와일드카드 관행은 있는데, `rsdAreaCd` ·
   `ageCd` 에 같은 값이 있는지는 코드표를 받아봐야 안다. 없다면 전국 수치 한 개를 위해
   **시군구 250여 개 × 연령 구간 × 성별을 전부 훑어야 한다.**
2. **사용자가 「호출제한 아주 적음」이라고 했다.** 위 1 과 정면으로 충돌한다. 안내
   페이지에는 호출제한·이용신청·인증키 발급에 대한 언급이 **아예 없다.**
3. **산업별·직종별 서비스가 없다.** `p67`(산업별 구인인원)과 `p65`(구인구직유형: 규모·
   임금·입사형태)를 `OPIA` 로 낼 수 있는지 불확실하다. `p66`(연령별 구직건수)은 `ageCd`
   로, `p64`(구인배수)는 구인/구직 합계 비율로 낼 수 있어 보인다.

**그래서 이 층은 「가능」으로 적지 않는다.** 먼저 할 일:
- 인증키 발급 절차와 실제 호출제한 확인 — **사용자가 해야 한다**(계정 생성·키 발급은
  내가 대신 하지 않는다).
- 코드표(`코드표 다운로드`)를 받아 `rsdAreaCd`·`ageCd` 에 전체 코드가 있는지 확인.
- 위가 확인되면 `p64`·`p66` 부터 착수하고, `p65`·`p67` 은 필요한 분류축이 API 에 없으면
  **수기 입력으로 남긴다.** 있는 척하지 않는다.

**호출제한이 적다는 제약이 설계를 정한다:** 조회는 **월 1회 수집 → 적재 → 캐시**이고,
화면 요청이 API 를 타는 경로는 만들지 않는다. 수집기는 재시도를 공격적으로 하지 않으며,
받은 응답 원본을 해시와 함께 보존해 재수집 없이 재현할 수 있게 한다(§3.1).

### 2.5 자동화할 수 없는 것 — 명시한다

`p161` `p188` `p189` `p190` 은 한국고용정보원 **패널 마이크로데이터 분석 결과**다
(청년패널·고령화연구패널, 종단/횡단가중값 적용, 결측치 처리). 공표된 표가 아니라 사람이
분석을 돌려야 나온다. 자동 수집 대상이 아니며, **수기 입력 경로를 유지한다.**
이것을 자동화한 척하지 않는다.

## 3. 설계 원칙 — 확정본이 수집기의 시험지다

이 프로젝트의 규율은 확정본 대조다. 수집기에도 그대로 적용한다.

> **수집기가 뽑은 수치를 수식에 먹여 확정본 값이 재현되지 않으면 수집기가 틀린 것이다.**

따라서 스캔 PDF OCR 도 안전하게 시도할 수 있다. OCR 의 통상 위험은 틀렸는지 알 수 없다는
것인데, 여기엔 정답표가 이미 있다. **정확도를 믿지 않고 측정한다.** 못 맞히는 층은 수기
입력으로 남긴다. 조용히 틀린 수치가 책자에 들어가는 경로는 만들지 않는다.

### 3.1 수집기 계약

수집기는 **원천 문서를 그대로 보존하고, 표를 long 형식으로 낸다.**

```ts
export type Collected = {
  source_id: string;      // 'nlrc_조정사건' 등. 저장소에 선언된 식별자
  fetched_at: string;      // ISO8601
  source_url: string;      // 실제로 받은 URL
  doc_sha256: string;      // 원천 문서의 해시 — 재현성의 근거
  doc_path: string;        // 보존한 원본 (hwpx/pdf/xlsx/html)
  rows: Array<Record<string, string | number>>;
};
```

- **원본을 버리지 않는다.** 해시와 함께 보존해야 「수치가 바뀐 이유」를 추적할 수 있다.
- **멱등이다.** 같은 문서를 다시 받으면 같은 행이 나온다.
- **부분 실패를 성공으로 보고하지 않는다.** 표 구조가 기대와 다르면 던진다.

### 3.2 적재 경로

층 0 은 기존 KOSIS 수집 경로에 표 ID 를 **추가**하는 것뿐이다 — `obs` 로 그대로 들어간다.

층 1 은 `별도데이터.xlsx` 를 대체하므로 `grid` 가 아니라 **long 테이블**로 적재한다.
새 테이블 `collected_obs(source_id, prd_de TEXT, dim1..dimN, itm_nm, unit_nm, dt)`.
`prd_de` 는 TEXT 다 (상위 스펙의 동일 규칙).

**이행 중에는 두 경로가 공존한다.** `grid` 의 별도데이터는 살려 두고, 수집기 산출물과
셀 단위로 대조해 **일치가 확인된 시트만** 수집 경로로 넘긴다. 한 번에 갈아타지 않는다.

## 4. 이 회차 범위 (층 0~1)

순서는 **싼 것 → 검증 가능한 것 → 불확실한 것**이다.

1. **층 0** — KOSIS 수집 목록에 누락 표 추가: `DT_1DA7007` `DT_1DA7006` `DT_1DA7A06`
   `DT_1DA7C06` `DT_1DA7E06` + `p35` 지역내총생산 표. 코드 변경이 거의 없고 확정본
   대조로 즉시 검증된다. 인수: `p49`·`p35` 의 확정본 값이 API 수집분으로 재현된다.
2. **출처 대장** — `A2`/`C2`/시트 1행에서 읽은 출처를 `provenance.json` 으로 물화한다.
   추정하지 않고 읽은 값만 담되, 읽히지 않은 지면은 **빈칸으로 남긴다.**
   (부수 효과: `C2` 가 목업의 「카드 상단 출처통계」 값이다.)
3. **문서 파서 골격** — 층 1-a 가 자료실 파일 다운로드이므로 이 회차에 필요하다.
   포맷 판별 → 표 추출 → long 행. `hwpx`·`pdf`·`xlsx` 를 같은 계약(§3.1)으로 낸다.
   스캔 pdf(OCR)는 이 골격의 뒤에 붙는 선택지이며, 정확도는 확정본 대조로 **측정**한다.
4. **층 1-a** — 중앙노동위원회 수집기 (`p116_117` `p118_119` `p120_121`, 704칸).
   웹페이지 → 자료실 목록 → 파일 다운로드 → 3 의 파서.
5. **층 1-b** — 한국생산성본부 수집기 (`p239_240`, 468칸). DB 조회 서비스 호출.
6. **층 0-b (조건부)** — EIS `OPIA`. §2.6 의 확인 셋이 끝난 뒤에만 착수하고,
   분류축이 없는 `p65`·`p67` 은 수기 입력으로 남긴다.

**인수 조건:** 관문에서 `etc` 때문에 막힌 셀이 **1,172 → 0**, 그리고 **불일치가 늘지 않는다.**
수집기마다 원본 문서를 해시와 함께 보존한다.

## 5. 미결정

- **EIS 인증키와 실제 호출제한** — 발급 절차·일일 허용 건수 확인 필요. 계정 생성과 키
  발급은 **사용자가 한다.** 코드표에 `rsdAreaCd`·`ageCd` 전체 코드가 있는지도 함께 확인.
- `p65`(구인구직유형)·`p67`(산업별 구인인원)에 필요한 분류축이 `OPIA` 에 없어 보인다.
  실제 응답으로 확인되면 수기 입력으로 남긴다.
- `p143` 은 확정본에 없다(도식화 지면). 별도데이터 시트만 존재.
- 층 2~4(공공데이터포털·고용부 첨부파일·산업재해현황분석 책자 PDF)는 다음 회차.
  `p128~p132` 5지면이 그 책자 하나에 걸려 있어 한 수집기로 묶인다. 3 의 파서를 재사용한다.
- 스캔 pdf 가 실제로 있는 대상은 아직 확인되지 않았다. 층 4(산업재해현황분석 책자)가
  후보다.
